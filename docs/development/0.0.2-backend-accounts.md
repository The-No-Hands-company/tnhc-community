# Alpha 0.0.2 accounts and follows — implementation verified

Date: 2026-10-04. Product version remains **0.0.0**. Target: **0.0.2**. This is a development record, not a release declaration.

## Implemented

- Local Supabase configuration, synthetic project fixtures, identity/profile/project/follow schema, row-level security, and bounded catalogue RPC.
- Invite-only account creation with administrator checks, expiring invitations, activation after Auth confirmation, and an Android deep link.
- Android Supabase repository, encrypted Auth session storage with Android Keystore, profile editing and visibility, password setup/change, sign-out, and persistent follows.
- A retry-safe invite function and explicit service-role permissions to inspect, create, consume, expire, and clean invitation records.
- Account-aware catalogue refresh: changing or ending a session immediately clears data belonging to the previous account.
- API contract, architecture, data-model, ADRs, local build instructions, and synchronized feature tracking for TNHC-003–005.

## Verification evidence

- Local PostgreSQL authorization suite: **64 assertions passed**, including two-account profile/project privacy, denied role grants, follow ownership and visibility, retry safety, and invitation service-role permissions. The four new grant checks failed before the migration was fixed.
- Invitation Edge Function: **8 Deno tests passed**; function type-check passed. The redirect test failed before the handler moved `redirect_to` into the Auth request URL.
