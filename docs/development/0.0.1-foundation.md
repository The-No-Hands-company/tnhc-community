# Alpha 0.0.1 foundation — development record

Date: 2026-10-03. Documentation revision: DOC-0002. Features: TNHC-001, TNHC-002. Status: **implemented, in review; not released**.

## Delivered source

- Native Kotlin/Compose application, API 26 minimum, compile/target API 36.
- Home, Projects, Community, Messages and Profile navigation with Android Back handling.
- Four fictional demo projects, category/text filtering and detail pages with stage, affiliation, interests and current focus.
- Empty catalogue, no-match, failed-load/retry and missing-project recovery screens.
- Saved tab, selected project, query and category; light/dark themes, scrollable content and keyboard insets.
- Future-feature explanations rather than simulated accounts, conversations or transactions.
- Gradle wrapper, Android build CI, developer setup and synchronised feature exports.

## Executed verification

Environment: Linux, OpenJDK 21, Gradle 8.13, Android SDK Platform 36 and Build-Tools 36.0.0. Due to quota and file-read stalls on the workspace disk, validation ran against an identical source copy on the system disk. All 25 source/build-input files were compared byte-for-byte with the workspace before retaining the build artifact.

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug :app:assembleDebugAndroidTest --no-daemon --no-configuration-cache
```

Result: **BUILD SUCCESSFUL**. Six unit tests passed, zero failures/errors/skips. Debug app APK and instrumentation-test APK compiled. Android lint reported zero errors and eight warnings: seven newer dependency/plugin versions and one recommendation to provide explicit Android 12+ backup/transfer rules. Dependencies are deliberately pinned; the application requests no permissions, uses no accounts and sets allowBackup=false. Review backup/transfer policy before introducing persistent member data.

Tests cover case-insensitive and trimmed search, title/summary/tag matching, combined category filters, clearing filters, empty/no-match results and unique fixture IDs. Before implementation, five of six tests failed against empty repository/filter implementations; the passing test covered empty/no-match behavior.

Evidence: [JUnit results](evidence/unit-tests.xml), [lint results](evidence/lint-debug.xml). Build artifacts are ignored by Git; the local APK is `app/build/outputs/apk/debug/app-debug.apk`. CI builds its own artifact from the committed source.

## Device verification limitation

There was no attached Android device. A temporary Android 16 (API 36) x86_64 emulator was downloaded and started twice. Emulator 37.2.12 exited with segmentation fault before appearing in ADB, both with the initial SwiftShader setup and with Vulkan disabled. The app was not installed or run on it. This host/emulator failure is not evidence about app runtime behavior.

Eight Compose device tests compile but have **not run**. The connectedDebugAndroidTest task was attempted and failed with `DeviceException: No connected devices!`. They cover destinations/detail/back, search reset, selected detail/query/category restoration, load retry, empty repository, restored-detail load failure/retry, system Back, and missing restored project recovery.

Both were corrected; corresponding restoration coverage was expanded, including category preservation and missing-project recovery. Device execution remains pending and is not implied by successful test compilation.
